# Savings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Count money set aside as savings (a Saving category kind, and a Savings account kind for confirmed transfers), and show it as its own table and summary line on Typical month.

**Architecture:** `resolve()` is unchanged for every existing consumer. A new `src/savings.js` decides, for each confirmed pair with exactly one side in a Savings account, which side counts and which Saving category (if any) it carries. `collect()` in `src/typical.js` uses that to feed a fourth table, `saving`, through the same row builder as the other three. Savings-account rows use a synthetic category id `account:<accountId>`.

**Tech Stack:** Vanilla ES modules, IndexedDB, JSDoc types checked by `tsc`, `node:test`, Playwright with axe.

**Spec:** `docs/superpowers/specs/2026-11-07-savings-design.md`

## Global Constraints

- Every CLAUDE.md rule applies: `textContent` only (via `h()`), no network code, no new dependencies, integer minor units, `divRound` for rounding, thresholds only from `src/tuning.js`.
- Savings never change Income, Living costs, Contributions, your share or Left over.
- A confirmed pair counts at most once, on its non-savings side, in that account's covered months only.
- Account-row synthetic ids are exactly `account:<accountId>`. A category UUID never starts with `account:`.
- `DATA_VERSION` becomes 3. `DB_VERSION` is unchanged.
- The PR description ends with: "After merging, tag the merge commit: `git tag data-v3 <merge-sha> && git push origin data-v3`".
- Never run `npm install` or `npm ci`. `node_modules` is a symlink to the main checkout.

## Review Focus

1. **Withdrawal pair (savings → bank) on a month the bank account doesn't cover.** It must count nothing, not a negative saving in a stray month. Test in Task 3.
2. **A pair whose non-savings side is a card account.** For example, a card refund paid into savings. It should count like a bank side. Test in Task 2.
3. **A confirmed pair where the transaction on one side has been removed by Undo.** The pair row stays, but the fingerprint has no transaction. `savingsContext` must not throw and must count nothing. Test in Task 2.
4. **Changing an account from Savings back to Bank.** Its pairs go back to plain transfers on the next render, with no stored leftovers. Test in Task 3.
5. **Upgrade of a v2 backup whose "Savings" category has odd fields**, such as an existing `budgetType`, or a name with spaces or different case. Only a Transfer-kind "Savings" is converted, and it ends with `budgetType: 'variable'`. Test in Task 1.

### Task 3: Typical month figures for savings (`src/typical.js`)

**Files:**
- Modify: `src/typical.js` (`counted`, `collect`, `totalsOf`, `monthFigures`, `typicalMonth`, `categoryDetail`, and the `Row`, `Totals`, `TypicalMonth` and `Collected` typedefs)
- Test: `tests/unit/typical.test.js`

**Interfaces:**
- Consumes: `savingsContext`, `accountRowId` (Task 2).
- Produces:
  - `Row` gains `accountId?: string`. It is set only on a savings-account row, whose `categoryId` is `accountRowId(accountId)`.
  - `Totals` gains `savings: number`, the sum of the `saving` rows.
  - `TypicalMonth` gains `saving: Row[]`.
  - `Collected` gains `rowCategories: Map<string, Category>`. This is `ctx.categories` plus one synthetic category per savings-account row seen: `{ id: accountRowId(a.id), name: a.name, kind: 'saving', budgetType: 'variable', position: 0 }`.
  - `categoryDetail` returns null for an `account:` id.

**Counting rules in `collect`** (from the spec):
- `res.source === 'transfer'` with a `sides` entry for `t.fingerprint`: treat it as one part, `{ amountMinor: t.amountMinor, categoryId: side.categoryId ?? accountRowId(side.savingsAccountId) }`, through the normal path. The natural figure is `-amountMinor`. Any other transfer: skip it, as now.
- Natural direction for kind `saving` is `-part.amountMinor`, as for spend.
- A part in a Saving category on a transaction whose account is in `savingsAccounts` is skipped. It counts for nothing.
- One-off Saving categories go to `oneOffs`, as now.
- Every `ctx.categories.get` used for a row lookup becomes `rowCategories.get`. That covers the main loop, the `monthOnly` loop and `monthFigures`. `tables` gains `saving: []`, and `tables[category.kind]` already works for it.
