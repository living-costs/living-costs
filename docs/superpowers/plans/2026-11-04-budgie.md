# Budgie Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Budgie, a browser-only app that imports bank and card CSVs, groups transactions into buckets, lets the user categorise them, and shows a typical month of living costs, with no data leaving the browser.

**Architecture:** Static `index.html`, plain ES modules under `src/` and one stylesheet, with no build step and no runtime dependencies. All domain logic lives in pure modules that take the in-memory `State` and return a `Changes` object. `src/store.js` applies `Changes` to memory and to IndexedDB in one transaction. The UI modules under `src/ui/` only render `State` and call domain functions. Because the domain logic is pure, `node:test` covers it in Node, and Playwright covers the screens.

**Tech Stack:** ES2023 modules, IndexedDB, DOM APIs, `crypto.subtle`, `Intl.NumberFormat`. Dev only: `node:test`, `tsc --checkJs --noEmit`, Playwright on Chromium with `@axe-core/playwright`, and a Node standard-library static server.

**Spec:** `docs/superpowers/specs/2026-11-04-budgie-design.md` (approved by the owner on 2026-11-04). `CLAUDE.md` holds the privacy and security rules. Executors read both.

## Global Constraints

- Transaction data never leaves the browser. Shipped code has no `fetch`, XHR, WebSocket, `EventSource`, `sendBeacon` or dynamic `import()`, and never builds a URL from user data.
- No runtime dependencies, no CDNs, no remote fonts or icons, and no external links in the UI.
- Render untrusted text with `textContent` or text nodes only. Never use `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `eval` or `new Function`. Never set a `style` attribute. Set `el.style.prop` through the CSSOM instead, because `style-src 'self'` blocks style attributes.
- `index.html` carries the exact CSP and referrer meta tags from `CLAUDE.md`, before any script in `<head>`.
- Money is integer minor units, debits negative and credits positive. A currency's exponent comes from `Intl.NumberFormat(…).resolvedOptions().maximumFractionDigits`. No floats in parsing or arithmetic. Divide with `divRound` only.
- Dates are ISO strings `YYYY-MM-DD`, and months are `YYYY-MM`. Day arithmetic uses UTC.
- Code reads every window and threshold from `src/tuning.js` and never hard-codes them.
- Never deletes a transaction automatically. Automatic suggestions never overwrite a user's choice.
- Real statements in `fixtures/` may be read, but nothing from them goes into code, tests, docs or commits. All committed fixtures are synthetic.
- Claude never runs `npm install`, `npm ci`, `npx playwright install` or `brew`. When a step needs a package, stop and ask the owner.
- Look and accessibility follow Mortgage Split: system font stack, tokens `--text #1a1a1a`, `--muted #3b3b3b`, `--bg #f4f4f2`, `--surface #ffffff`, `--border #595959`, `--accent #0b3d91`, `--accent-contrast #ffffff`, `--banner-bg #fff4d6`, `--intro-bg #e8f1fb`, `--focus #0b3d91`. Use 3px solid focus outlines, 44px minimum target height, reflow at 320px without horizontal scroll, and `aria-hidden` decorative bars with the table holding the data.
- axe tags are `['wcag2a', 'wcag2aa', 'wcag21a', 'wcag21aa', 'wcag22aa']`.
- Single-key shortcuts are active only while focus is inside the categorise card.
- UI text is short and plain, in British English.

## Decisions this plan adds

The spec leaves these to the builder, or is silent on them. **D1 needs the owner's OK.** It changes typical-month numbers in a case the spec covers.

- **D1. Per-account months (needs owner OK).** As written, the spec divides every category by the window's month count. An account that starts later, like the joint account imported only from August, would then be averaged over 12 months while holding 3 months of data. A £550 monthly contribution would show as £137.50. This plan instead counts each transaction only in window months that its own account fully covers, and divides by that account's count of covered window months. When every account covers the whole window, the results equal the spec's formulas exactly. The formulas are in Task 22.
- **D2. A month nobody covers isn't complete.** The spec's rule ("every account with coverage both before and after the month covers it") is vacuously true for a month after all data. So a complete month also needs at least one non-placeholder account to cover it fully.
- **D3. Overlap review only inside already-covered dates.** An incoming row goes to review only if its date falls inside the account's existing covered period. Otherwise next month's first £3.50 coffee would be "held for review" against last month's coffee.
- **D4. Normaliser hyphen pieces.** Step 4 splits on whitespace and hyphens and drops pieces with 4 or more digits, so `REF-202601-99887766` becomes `REF`, not nothing. The spec says "whole", but splitting on hyphens can't remove `REF`. The key stays stable from month to month either way.
- **D5. Model adjustments**, which the spec allows:
  - The mapping is embedded in `Account.mapping`, with no separate store.
  - `Bucket.keys[]` replaces `key`, because merging collects keys.
  - `categorySource` is dropped, because v1 has no automatic categorising.
  - Added fields: `Account.identifier`, `Transaction.flaggedRuleId`, `Override.flagDecision`, `Category.position`, `Settings.helpDismissed` and `TransferPair.key`.
  - Amount rules use `matchType: 'keyAmount'`, and their `pattern` is a bucket key.
- **D6. Card queue.** The categorise card also shows categorised buckets that hold unresolved flagged amount-rule rows. Otherwise flags would never surface once the source bucket is categorised.
- **D7. Banned-pattern scope.** The check scans what ships: `index.html`, `styles.css` and `src/**`. Tests and tools legitimately contain `http://localhost`.
- **D8. Builder's choices:**
  - Text similarity is the Dice coefficient on character bigrams.
  - "Regular interval" means a median gap in a period band, with at least 80% of gaps in that band.
  - Percentiles use the nearest-rank method.
  - The median of an even count averages the two middle values with `divRound`.
  - The backup filename is `budgie-backup-YYYY-MM-DD.json`.

## Review Focus

These are the inputs most likely to bite real users that the spec doesn't spell out. Each one has a test in the task that owns it.

1. **A non-UTF-8 export**, such as Windows-1252 with a raw `£` byte. Descriptions should still read correctly and not show `�`. Task 5 tests a fatal UTF-8 decode that falls back to `windows-1252`.
2. **Footer rows, totals rows, or rows with the wrong number of cells.** These should be listed as parse errors with row numbers, never silently misread. Covered in Tasks 5 and 6.
3. **Undo, re-import, or restore, then re-import.** Overrides, splits, transfer decisions and flag decisions should all reattach. Covered in Tasks 10, 12, 19 and 24.
4. **Deleting a category or merging buckets** while overrides, splits, rules, placeholder links or bucket categories point at them. Nothing should be left dangling. Covered in Tasks 10 and 17.
5. **An account whose latest statement ends before the others'.** That month must not look complete with its data missing, and the typical month must say which account is behind. Covered in Tasks 11 and 22, and shown in Task 23.

## Phase 4: Typical month

### Task 22: Typical-month calculation and reconciliation

**Files:**
- Create: `src/typical.js`, `tests/unit/typical.test.js`, `tests/unit/reconcile.test.js`, `tests/unit/helpers/fixture-state.js`

**Interfaces:**
- Consumes: `analysisWindow`, `staleAccounts` (Task 11), `resolve` (Task 16), `divRound` and `tuning`.
- Produces:
  - `typicalMonth(state, tuning): TypicalMonth`
    - When the currencies are mixed, it returns `{mixedCurrencies: true, currencies: string[]}`.
    - Otherwise it returns `{currency, months: string[], complete: boolean, stale: Account[], spend: Row[], income: Row[], contribution: Row[], oneOffs: {txn, categoryId, amountMinor}[], uncategorised: {spending: number, income: number}, totals: {income, living, contributions, share, leftOver}}`.
  - `Row = {categoryId, name, budgetType, perMonth, perYear, range?: [number, number]}`. All values are positive in the category's natural direction: spend shows money out, and income and contribution show money in.
  - `fixtureState(): Promise<State>`, a test helper. It imports every fixture through the pure pipeline with full-year covered periods for A, S and C and whole months for B. It sets the bucket categories from `expected.intendedCategories`, creates amount rules for −299 (`Google One storage`) and −999 (`Streaming`), both monthly ×1, in Subscriptions, marks `OTHER CARD PLC` as the placeholder `Other Card`, and confirms every suggested pair.

**Calculation (D1).** Let W be the window months, and `n_a = |accountMonths(a)|`.
- A transaction part counts only if its month is in `accountMonths(account)`.
- It also has to resolve to a category of kind `spend`, `income` or `contribution`. Transfers, `ignore` and `none` are left out. `none` goes to the uncategorised line instead.
- For each category C and account a, the series is the net monthly totals over `accountMonths(a)`, with months that have no rows counted as 0, signed toward the natural direction.

| Type | perMonth | perYear | range |
|---|---|---|---|
| `fixed` | Σ over (bucket b, account a) active in the last `fixedActiveMonths` of W: `divRound(latestCharge × chargeCount, n_a)`, plus Σ_a `divRound(oppositeSignTotal_a, n_a)` | perMonth × 12 | none |
| `variable` | Σ_a median(series C,a) | perMonth × 12 | [Σ_a P(lo), Σ_a P(hi)], using `variableRange` |
| `annual` | `divRound(perYear, 12)` | Σ_a `divRound(total_a × 12, n_a)` | none |
| `oneoff` | not in tables. Each counted part goes in `oneOffs` | | |

  A "charge" has the category's natural sign. The latest charge is the one with the newest date. Median and percentiles follow D8.

- Totals:
  - `living` = Σ spend perMonth
  - `contributions` = Σ contribution perMonth
  - `share` = living − contributions
  - `income` = Σ income perMonth
  - `leftOver` = income − share
- `uncategorised` sums the counted parts that resolve to `none`, over the whole window, with debits and credits kept separately and shown as positive values.
